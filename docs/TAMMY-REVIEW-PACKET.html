The five-step flow, broken down.

This page goes deeper into the same New Transaction Flow shown on the homepage. Same sample deal: Jordan Patel buying 1128 4 Street SW from Maple Retail Holdings Ltd. Same five steps. Just more detail on what runs and what stays a draft.

Sample data only. No emails are sent. Live Google account hookup is a separate setup step covered in the deploy notes.

01 / Signed agreement

Realtor uploads the signed DocuSign agreement.

Exclusive Buyer Agreement or Exclusive Seller Agreement. The system reads it, detects buyer or seller side, and uses it as the trigger for every downstream step. No retyping.

Stack: DocuSign → Apps Script.

02 / Drive folder

Apps Script creates the client folder.

Folder name matches the transaction ID and address. The subfolder taxonomy is the one you already use: Initial Prospect, Full Info Prospects, Financials, Monthly Sales, Franchise & Lease, Payroll, Incorporated Docs, Store Photos, Normalized Financials. No manual setup per deal.

Stack: Apps Script → Google Drive.

03 / Calendar reminders

Two reminders land on the calendar.

One for the condition waiver deadline, one for possession. Each event description carries the transaction ID and the buyer name so the reminder reads correctly in any view. Auto-attached to the calendar Apps Script uses, not your personal one.

Stack: Apps Script → Google Calendar.

04 / Trade record + Realtor checklist

The row writes back to the workbook. The validation checklist sits at the bottom.

Claude extracts buyer, seller, sold price, sale date, possession date, MLS number, contract number, and both realtor names from the agreement. The row writes back with the source filename so you can trace it. Below the row, the Realtor validation checklist tracks signed agreement, purchase contract, deposit, condition waiver, MLS listing, and trade record review.

Stack: Claude → Google Sheets.

05 / Draft email

A client follow-up is staged in Gmail.

The draft uses the extracted fields. Subject line includes the address. Body opens with the buyer name and lists the next-step items in plain language. It stays a draft until a human opens Gmail and hits send. The script never auto-sends.

Stack: Claude → Gmail (draft only).

Required docs

What is in and what is missing.

The dashboard shows expected, received, and missing docs at a glance. The condition waiver is left visible to show the missing-doc row.

What is real
  • Apps Script reads the intake row from the Sheet and creates the Drive folder.
  • Claude extracts the trade record from the source PDF.
  • Calendar reminders are added with the buyer name and transaction ID.
  • The Gmail draft is written from the extracted fields.
  • Every action gets logged to a sheet with timestamp and outcome.
What is faked or held back
  • Sample client and property data only — no live transaction records.
  • Drafts never auto-send. The script generates and stops.
  • Apps Script runs against a test Google account, not the production inbox.
  • One condition waiver is left missing on purpose so the missing-doc row is visible.
  • Apps Script project ID and Drive folder ID are placeholders on this page.
