Roundtable Walk-Through

From source document to drafted follow-up.

This demo follows one new transaction from the moment a source document is selected through review, folder and reminder setup, and a drafted client email. The point is to show a workflow that a broker or realtor can understand quickly without losing the human gate at the moments that matter.

This walk-through uses sample data. Gmail stays in draft-only mode, so no email leaves the account.

01 / Intake

The transaction starts from one selected document.

Instead of retyping details into a new record, the operator points the workflow at a source file such as an executed purchase agreement. That source becomes the starting point for the transaction.

02 / Extraction

The document is read and normalized before work continues.

The workflow extracts the core transaction details, checks for missing fields, and records the result directly on the row. If the minimum information is not present, the operator sees that before the workflow moves downstream.

03 / Review

A human approves the transaction before the next step.

The stable pause point is review-ready, not auto-send. That means the operator can approve, reject, or reverse approval without losing track of the current attempt, source lineage, or notes.

04 / Setup

Folder and reminder setup wrap around the deal.

Once review is approved, the workflow can prepare the surrounding structure: where the files belong, what reminder or follow-up surfaces should exist, and how the transaction stays organized after intake.

05 / Draft

The client email is staged as a draft.

The drafted follow-up is grounded in the source document and normalized fields, then left for a human to review before sending. It helps the operator move faster without pretending the last mile should be automatic.

Document check

What was found is visible.

The operator can point to the readiness check, the missing-field summary, and the status shift into review.

Trade record

The row is the control surface.

Attempt state, source lineage, next-step actions, and draft linkage all stay tied to the current transaction.

Draft email

The draft is ready for human review.

The workflow stages a client-facing message without crossing into auto-send or hiding the source context.

Why This Matters

This is meant to reduce the repeated setup work that comes with every new transaction: document reading, checking what is missing, getting the record into a stable state, and preparing a client follow-up without starting from a blank page each time.

The strongest part of the story is not abstract AI capability. It is the fact that the workflow stays grounded in one transaction and one source document while still keeping the operator in control.

Where AI Helps
  • Reads the selected source document for transaction details.
  • Flags missing or incomplete information before work moves forward.
  • Normalizes extracted details into the working record.
  • Grounds the drafted email in the source and extracted fields.
